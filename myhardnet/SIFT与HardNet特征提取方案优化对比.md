# SIFT 与 HardNet 特征提取方案优化对比

更新日期：2026-10-22。适用范围：当前 Python 工程、本机 CPU 部署、约 400 个关键点、1:1 验证和每身份 40 张注册模板。

本文是优化与实验方案，不改变训练、匹配配置或模型权重。性能数据引用 2026-10-20 的既有测量；未测方案明确标为待验证，不将理论计算量换算成推理耗时。

## 1. 建议与结论

1. **部署性能基线：SIFT 检测 + MobileHardNet256 + Hadamard256。** 这是目前具有本机时间与增量内存达标证据的组合；识别精度仍需独立评估。
2. **传统描述子基线：SIFT / RootSIFT128 + L2。** 用于判断学习式描述子的真实收益与二值化损失。它们不是最终二值输出方案，当前正式匹配入口也没有完整的纯 SIFT 特征生成分支，需要补齐对照适配器。
3. **优先验证的精度优化：MobileHardNet256 + learned256，比较冻结主干与联合微调。** 先保留现有浮点特征维度，再比较 128 / 256 / 512 bit；当前 YAML 的 512 bit、冻结主干设置不因本文建议而改变。
4. **无 CNN 的二值备选：RootSIFT128 + Hadamard128。** 实现成本相对可控，但必须验证量化损失；只有后处理组件可以复用，不能直接切现有模型开关完成整条路线。若短码精度不足，再考虑 RootSIFT128 + learned256。
5. **优化先后：复现实测配置 → 控制线程与批次 → 优化 patch 数据流 → 补齐 SIFT 对照 → 二值学习实验。** 从零训练作为消融实验；INT8 作为后续改变推理精度的独立实验。

用户已确认：**精度只要求在相同 FAR 下比较 FRR，暂不固定 FAR 数值。** 本文不替产品制定新的精度门槛，也不宣称某个描述子一定更准。

## 2. 验收边界

以下要求继承自[模型性能约束](模型性能约束.md)：

- 设备与主验收环境：AMD Ryzen 9 5900HX，Windows，CPU FP32，ONNX Runtime；记录实际 OpenCV、PyTorch 和 ORT 版本。
- 时间：预热后，内存灰度图 → 检测与有效点筛选 → 描述子生成 → 二值化与打包，整段 **p95 < 70 ms**。HardNet 路线必须包含 patch 裁剪、标准化；SIFT 路线必须包含原生描述子计算，不能只测 `SIFT.detect`。
- 内存：模型和 40 张注册模板常驻，完整识别路径预热；单请求开始至最终身份判定的最大 `ΔRSS < 30,000,000 bytes`。匹配、候选、RANSAC 和纹理验证均纳入内存采样。
- 时间终点是描述子就绪，内存终点是身份判定结束，两者不同。
- 同时披露常驻 RSS、绝对峰值、首次扩容、采样间隔及并发数；低增量不代表进程总内存低于 30 MB。
- 约 400 个点应为实际有效输出，报告检测数、筛选数与最终描述子数；不能靠大幅减点、复用查询结果或补重复 patch 获得正式达标结论。

本轮既有测量不包含磁盘读取、解码与上游去噪，且关闭了缺失的 mask / quality 产物依赖。重新纳入这些步骤或更换设备后，需要重新测量，不能沿用通过结论。

## 3. 现有实现：两条路线共享 SIFT 检测

### 3.1 传统描述子路线

```text
图像 → SIFT 检测位置、尺度与方向 → SIFT128 → 可选 RootSIFT → L2 匹配
```

数据构建的 [positive_builder.py](pair_build/positive_builder.py) 已使用 `detectAndCompute`、RootSIFT 和 `BFMatcher(NORM_L2)` 生成正样本。RootSIFT 是直方图归一化与平方根变换，仍为 128 维连续描述子，不是二值码；项目在变换后还执行 L2 归一化。[RootSIFT 原论文](https://robots.ox.ac.uk/~vgg/publications/2012/Arandjelovic12/)

### 3.2 当前 HardNet 路线

```text
图像 → SIFT 检测位置与方向 → 筛点 → 对齐的 32×32 patch
     → MobileHardNet / HardNet → 浮点特征 → Hadamard 或学习式二值头 → 打包
```

[runtime.py](match_new/runtime.py) 只调用 `sift.detect`，不额外计算 SIFT 描述子；[template_builder.py](match_new/template_builder.py) 随后裁 patch 并生成 HardNet 描述子。HardNet 本身是局部描述子网络，不负责检测整图关键点。[HardNet 原论文](https://arxiv.org/abs/1705.10872)

因此，不能把“SIFT 检测时间”当作“SIFT 描述子整条路线时间”，也不能把 HardNet 的时间写成不含 SIFT 的单次 CNN 时间。

当前适配边界：

- `match_new` 底层仍有 SIFT / RootSIFT 的 float32 / L2 模板读取与匹配接口，但正式模板构建入口生成的是 HardNet 模板；纯 SIFT 主流程不是现成的配置开关。
- 当前 HardNet patch 使用固定裁剪尺寸和关键点方向，没有按 SIFT 的 `size` 自动缩放支持区域。原生 SIFT 的尺度支持与其不同，比较时需要披露这一差别。
- 工作区没有可检查的 `finger/` C++ 源码，旧文档中的相关路径不能作为当前 C++ 实现或速度的证据。
- m2 / Strong V2 已移除，不再作为可实施候选。m0 和 m1 保留；训练默认已是 m1，但当前匹配配置仍指向 m0，这不等于已部署下面的达标组合。

## 4. 方案与优化对比

### A0：SIFT / RootSIFT128 FP32，传统精度基线

- 优点：无需训练 CNN；RootSIFT 后处理简单；便于分析关键点、传统描述子与二值化各自的影响。
- 局限：每码 512 bytes，使用 L2；不满足最终 packed 二值描述子的接口要求。本项目尚无同条件 70 ms / 30 MB 及身份精度对照。
- 优化：缓存 SIFT 实例；注册模板离线计算并常驻；已有 SIFT 描述子可转换 RootSIFT；比较 `detectAndCompute` 与提供关键点后 `compute` 的实际代价，避免重复检测或重复建尺度金字塔。
- 实现工作：增加独立对照适配器，复用身份库、候选、几何与纹理验证；保持描述子和返回关键点的行对齐。

### A1：SIFT128 CV_8U，存储压缩对照

- OpenCV 支持 `CV_32F` 和 `CV_8U` 两种 SIFT 输出类型。`CV_8U` 表示 128 个数值分量占 128 bytes，即 1024 bit 存储，**不是 128 bit 的二值描述子**。[官方 API](https://docs.opencv.org/4.13.0/d7/d60/classcv_1_1SIFT.html)
- 仍按数值直方图使用 L2 等适当距离，不能直接改成 Hamming。官方 SIFT 的 `defaultNorm()` 为 `NORM_L2`。[官方实现](https://github.com/opencv/opencv/blob/4.13.0/modules/features2d/src/sift.dispatch.cpp)
- 可验证内存与匹配代价，但当前 SIFT 模板契约会转 float32，直接设置输出类型不能实现端到端压缩。
- RootSIFT 的平方根变换会产生浮点值；不能简单把 RootSIFT 强转 uint8，声称保留其匹配性质。

### A2：RootSIFT128 + Hadamard128，固定二值化备选

- 输出 128 bit、每码 16 bytes；复用现有 FWHT 的计算组件，无额外 CNN 或学习参数。
- 需要补齐 SIFT 特征生成、描述子家族标识、128 阶变换配置、模板契约与实验入口；当前 Hadamard 默认 order=256 不能直接套到 128 维 SIFT。
- 理论风险：取符号会丢失幅度；正交变换在取符号前的距离性质不保证取符号后的 Hamming 排序。
- 特别检查位熵：RootSIFT 非负，非零描述子经标准 Sylvester Hadamard 后，第一项是所有分量之和，因此该位恒为 1。这是数学推论，不是实测精度结论；其余位也需要检查均衡、相关性和跨拍摄稳定性。
- 不通过补零或复制特征，把 128 bit 包装成“新增了有效信息的 256 bit”；若采用额外投影，应单列新方案。
- 定位：测试“无 CNN、短二值码”能否满足当前身份识别精度，不预设它比 HardNet 更快或更准。

### A3：RootSIFT128 + learned256，学习式编码备选

- 固定 SIFT 特征，训练映射到 256 bit 的编码头；具有针对真实对应关系调整量化的空间，且不运行图像 CNN。
- 需要新的 SIFT 特征数据入口与训练适配。当前 `train_binary.py` 强制加载浮点 CNN checkpoint，不能直接当作 SIFT 哈希头训练入口。
- 这里训练的是编码头，不是对 SIFT 手工描述子进行 CNN 式的主干联合微调。
- 若复用当前默认残差头，D128 / B256 新增 363,264 参数、360,448 MAC/patch；只包含线性层 MAC，不包含 SIFT 计算、归一化、激活或匹配。因此不能据此推断整段耗时。
- 优先级低于 A0 / A2 与现有 Mobile 基线；只有传统描述子有竞争力且固定量化损失明显时，再投入训练。

### B0：MobileHardNet256 FP32，学习特征精度基线

- 每码 1024 bytes，L2 匹配。主要用于与 B1 / B2 对照量化损失，不作为最终二值交付方案。
- 采用相同关键点、patch 和 checkpoint，只切换后处理，有助于区分“浮点特征不足”和“二值化损失”。

### B1：MobileHardNet256 + Hadamard256，当前部署性能基线

- 当前可复用代码与已有 m1 权重；输出 256 bit、每码 32 bytes，无需重新训练二值头。
- 既有本机结果：生成 p95=62.5387 ms；完整 40 模板请求最大观测 ΔRSS=4,837,376 bytes，满足本轮性能门槛。
- 主要优化方向：先复现线程与 batch，再优化裁剪、标准化和中间数组；保持现有 CNN 与变换，便于验证性能改动的描述子一致性。
- 局限：固定变换不能根据指纹匹配目标学习编码；性能通过不代表 FRR 优于其他方案。

### B2：MobileHardNet256 + learned256，优先精度实验

- 第一组比较冻结主干和浮点预训练后联合微调；随后用 128 bit 检查压缩收益、512 bit 检查增加码长的精度收益。
- 浮点维度 D 与码长 B 独立。优先保留已有 D256；在 Mobile + learned256 下改 D128，总 MAC 只减少约 1.1%，却需适配末端权重。
- 当前头的线性层 MAC 为 `D×B + 5B²`。Mobile D256 / B256 合计 509,040 参数、5,397,504 MAC/patch；B512 合计 1,560,176 参数、6,446,080 MAC/patch。MAC 不包括归一化和激活，不能等比例预测延迟。
- 当前外部 CPU 后端运行 CNN，学习式头仍由 PyTorch 执行。可实验将“主干 + 连续 logits”一并导出到 ORT，在外部阈值化和打包，验证后端切换开销及算子支持。
- 联合微调需控制主干学习率及过拟合；当前 teacher 来自同一主干，`detach()` 不等于固定旧教师。已有冻结二值 checkpoint 也不能直接改开关后当作同一实验 `--resume`。
- 从零联合训练只作为同结构、同数据的初始化消融；当前 CLI 尚不支持，不能列为可直接运行的方案。
- 现阶段缺少 Mobile 学习式二值方案的同条件完整实测，不能继承 B1 的通过结论。

### B3：m0 / 原 HardNet，保留研究对照

- m0 D256 为 2,384,032 参数、40,140,800 MAC/patch；m1 D256 为 112,752 参数、5,004,288 MAC/patch，均只计 CNN 卷积/线性乘加。
- 既有 m0 + Hadamard 的已测配置 p95 均超过 70 ms；m0 + learned512 初筛同样未通过。暂不优先投入部署优化，作为精度参考保留；不能由有限配置的失败推导所有未来实现都必然失败。

## 5. 优化实施顺序与预期影响

### P0：复现可用基线，避免比较配置差异

1. 显式使用既有 m1 checkpoint `outputs/models/3/m1/m1_256_v2/best.pt`，记录 SHA-256 与模板版本。
2. 实验覆盖 ORT intra-op=8、inter-op=1、batch=64、fixed batch=0、OpenCV=1、PyTorch 后处理=1；保留 FP32。它们是已测组合，不是任意模型和设备上的全局最优。
3. 注册模板离线生成，模型和模板常驻；每次查询仅提取一次描述子，再依次比较 40 张模板。已有缓存机制应先复用，不把重复实现当作优化。
4. 固定图像预处理与 mask / quality 策略，复核已测结果的适用边界；不同方案使用独立输出和模板目录。

ORT 的算子内并行由 intra-op 控制；inter-op 池只在并行图执行模式下发挥作用。线程数更多不意味着延迟更低，应同时控制 OpenCV、ORT 和 PyTorch 的线程竞争。[ORT 线程说明](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)

### P1：HardNet 数据流与内存

- 已实现：按输出 patch 构造反向映射、缓存网格、`remap` 局部采样、批量标准化、CNN 分批；不再逐点旋转整图。
- 仍可实验：将“全部 patch 堆叠并标准化 → CNN 分批 → 合并输出后 Hadamard”改为“64 点裁剪与标准化 → CNN → 立即二值化并写入预分配结果”。当前 batch=64 只限制 CNN batch，不代表整条路径已流式处理。
- 400 个 FP32 32×32 patch 净数组为 1,638,400 bytes；64 个为 262,144 bytes。流式处理有机会降低中间驻留与重复分配，但真实峰值还包含归一化临时量、算子工作区和 ORT arena，且小批次调度可能抵消速度收益。
- 保持关键点顺序、插值、边界补零、标准化 epsilon 和有效行数一致；使用描述子差异、bit 翻转率及最终 FAR/FRR 验证等价性。
- 先验证串行分块，再考虑裁剪与推理重叠；并行流水线可能和 ORT 争用 CPU，不能预设更快。

### P1：两条路线共用的检测与选点

- 当前 SIFT 参数为 nfeatures=500、nOctaveLayers=3、contrastThreshold=0.03、edgeThreshold=17.5、sigma=1.70；匹配端后续最多截取 400 点。`nfeatures` 是保留的最佳特征数量上限，不是“每层 500 点”。[OpenCV 参数语义](https://docs.opencv.org/4.13.0/d7/d60/classcv_1_1SIFT.html)
- mask 限制关键点中心，不保证省掉整图尺度金字塔开销。裁 ROI、缩图或降低尺度层数都可能改变位置、方向与可重复性，须单独消融。
- 可比较 response 截断与空间均匀选点，观察真实对应率、几何内点及最终 FRR；避免 400 点集中在重复脊线区域。均匀选点本身也有计算成本。
- 当前先截 400 点再过滤 patch 越界，所以实测输出可少于 400。可实验先做有效性筛选再选点，但由此增加的描述子数量必须计入工作量，不能把选点策略变化当作纯提速。
- 更改检测、方向或 patch 分布时，应复核训练数据契约；只对某条路线开启增强、降噪或质量放宽，会污染描述子对比结论。

### P2：模型与精度变更

- 对 B2 优先做联合微调与码长消融，使用同一数据划分、预算和多个随机种子；不先扩大主干。
- 对 A2 先比较原 RootSIFT 与二值码的近邻排序、位均衡和真实对应保留率，再决定是否做 A3。
- INT8 权重/激活量化与最终二值描述子是不同层面的优化。当前主验收为 FP32，INT8 需另列实验；CNN 可考虑带代表性校准数据的静态量化，但算子支持、量化开销和 CPU 指令能力均会影响结果，不能承诺 4 倍提速或不损失精度。[ORT 量化说明](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)

## 6. 存储、匹配与增量内存

以下按每图恰好 400 码、每身份 40 张图计算，仅为描述子净载荷；不含关键点、纹理图、文件压缩、容器、模型和运行时：

- SIFT / RootSIFT128 FP32：每码 512 B；每图 204,800 B；40 模板 8,192,000 B。
- SIFT128 CV_8U：每码 128 B；每图 51,200 B；40 模板 2,048,000 B；仍不是 packed 二值码。
- HardNet256 FP32：每码 1024 B；每图 409,600 B；40 模板 16,384,000 B。
- packed128：每码 16 B；每图 6,400 B；40 模板 256,000 B。
- packed256：每码 32 B；每图 12,800 B；40 模板 512,000 B。
- packed512：每码 64 B；每图 25,600 B；40 模板 1,024,000 B。

模型和注册模板已常驻，因此上述 40 模板净载荷不是本次 ΔRSS；最终码小，也不能证明请求峰值达标。

匹配优化原则：

1. 保留 CPU 的 OpenCV packed-Hamming top-k 路径，按模板逐个比较；ratio test 即使只接受一个候选，也需要最近和次近距离。
2. 若构造 400×400 的 FP32 全距离矩阵，单个净数组为 640,000 B；同时保存 40 份就是 25,600,000 B，还未包含索引和其他临时量。避免一次堆叠全身份的所有距离矩阵。
3. 避免实现 `q[:,None,:] - g[None,:,:]` 的浮点三维差值；D128 / FP32 的该数组净大小已为 81,920,000 B。也避免用三维广播 XOR 取代当前 CPU 实现：B256 的单个 XOR 数组即 5,120,000 B，后续查表与求和还有额外空间。以上是错误实现风险的估算，不是当前 CPU 路径的实测占用。
4. 小规模 1:1 验证先用精确匹配；引入近似索引前，必须证明索引常驻成本与漏召回风险有收益。当前规模不自动需要全库 ANN 方案。
5. 40 模板用同一融合与提前停止规则；同时报告真实执行模板数。加入早停可降低平均匹配耗时，但不能替代完整遍历与重分支的峰值内存测试。

- m1 + Hadamard256：3 张图循环测 100 次，实际输出 394 / 391 / 389 码；p50=58.3246 ms、p95=62.5387 ms、max=82.5050 ms。
- 同一组请求的阶段均值：SIFT 检测与截断 5.6143 ms；裁剪与标准化 19.6937 ms；描述子计算与后处理 33.2996 ms；总均值 58.6076 ms。各阶段均值可对账；**各阶段 p95 不能相加当作整段 p95**。这里的 SIFT 阶段没有计算 SIFT 描述子，describe 阶段也不等于纯 CNN。
- 完整 1:1 / 40 模板：预热 12 次，再测 20 次；baseline=298,139,648 B、最大 peak=302,977,024 B、最大 ΔRSS=4,837,376 B。
- 首次描述子请求扩容 36,241,408 B；按预热后口径排除于硬预算，但应保留披露。
- 内存采样目标间隔 1 ms，验收请求最大实际间隔约 10.30 ms；采样峰值不是所有瞬时峰值或所有识别分支的严格上界。
- 既有 m0 已测配置的生成 p95 超限；纯 SIFT、SIFT 二值化和 Mobile 学习式方案没有本轮同条件验收与精度对照。

由这组均值判断，继续只压缩约 5.6 ms 的检测阶段不能解决所有问题；裁剪 / 标准化与推理 / 后处理更值得分阶段分析。不能将这些均值套到 SIFT 描述子整条路线或其他图像大小。

## 8. 对照实验与验收步骤

### 8.1 先分离描述子差异，再比较完整路线

1. **固定位置对照**：相同图像、预处理、mask、关键点坐标、方向和有效点集合，分别计算 SIFT / RootSIFT 与 HardNet 描述子。SIFT 的尺度支持和 HardNet 固定 patch 支持仍不同，需要记录；若强行统一尺度，作为额外消融，不冒充原生 SIFT。
2. **完整路线对照**：分别运行各方案实际检测与描述子实现。SIFT 路线可测试避免重复金字塔构建的原生调用；HardNet 路线使用 detect + patch + CNN。验收计时都从图像开始，不能复用固定位置对照中预先缓存的关键点。
3. **二值化消融**：A0→A2 / A3，以及 B0→B1 / B2，分开衡量传统 / 学习特征与量化的收益和损失。
4. **码长控制**：不同码长用于比较资源与精度折中，不能当成等存储条件；纯描述子方法比较应增加等码长对照。128 维 SIFT 不要求只能学习 128 bit，但固定 H128 路线本身输出就是 128 bit。

### 8.2 精度协议

- 按身份隔离训练、验证与最终测试；保持现有划分，检查同一真实手指跨目录或近重复图像的泄漏。SIFT 生成的训练正样本可能带来标签偏差，建议用独立人工核查 / 几何核查的对应集补充验证。
- 各方案在验证集分别调整 ratio、绝对距离和最终身份阈值，再冻结到测试集；不沿用 SIFT / L2 阈值到 Hamming，也不在测试集选阈值。
- 比较最终身份级 ROC / DET 与相同 FAR 下的 FRR，不以 patch 检索指标、平均距离或几何内点数量代替身份精度。
- 当前未固定 FAR 数值；选择双方均有数据支持的共同工作点，并报告实际达到的 FAR、FRR、试验数和区间。分数离散时给出可实现的相邻阈值，不用未经说明的插值制造精度。
- 不能凭有限样本“零误接受”宣称任意低 FAR。多模板、多次查询具有相关性，应按身份分组估计不确定性；补充质量、干湿、噪声与旋转条件分组。
- 主对照固定 40 张注册图、相同查询集合、相同融合与几何 / 纹理后端，关闭动态模板学习；描述子敏感阈值可分别校准。质量自适应策略先固定，再单独评价其收益。
- 同 FAR 下 FRR 的可接受回退幅度尚未确定，因此本轮不能仅凭更快就认定最终胜出。

### 8.3 性能与最终选择

- 第一轮可按既有 15 次生成预热、100 次计时、12 次完整识别预热和至少 20 次内存观测复现；这是复现起点，最终还需扩大图像与分支覆盖。
- 单线程请求、相同设备和后台负载，记录版本、checkpoint SHA、实际后端、线程、batch、每图有效点数、p50 / p95 / max 和 percentile 算法。
- 覆盖接受早停、拒绝完整遍历、候选多、RANSAC / 纹理实际执行、低质量和边界图像；随机交错方案顺序，减少温度 / 频率漂移影响。
- 模板变更使用独立目录与版本。SIFT / HardNet、浮点 / 二值、不同权重 / bitorder / 变换和预处理不可混用模板；同样 256 bit 不代表编码兼容。
- 先筛选同时满足二值接口、p95 和 ΔRSS 的方案，再在共同 FAR 下比较 FRR；无明显精度差异时，优先实现和维护成本较低者。正式切换前仍需用户确定精度与资源的最终取舍。

## 9. 建议执行清单

1. P0：保存 m1 + Hadamard256 可复现配置，扩大本机性能样本，并建立独立身份级精度基线。
2. P1：补齐 SIFT / RootSIFT128 的对照入口与相同数据后端；记录传统特征整段时间，避免把已有 detect 数据误用为整段性能。
3. P1：单独实现并验证 HardNet 分块裁剪 / 标准化 / 输出打包，量化速度、峰值和 bit 一致性。
4. P1：Mobile D256 / learned256 冻结与联合微调对照；精度或预算需要时再测 B128 / B512。
5. P2：RootSIFT128 + Hadamard128；只有传统基线有竞争力且量化损失需要修复时，再做 learned256 头。
6. P2：从零训练、INT8、不同检测器或更复杂索引分别立项消融；不与主对照同时改动。
