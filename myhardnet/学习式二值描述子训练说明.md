# 学习式二值描述子训练说明

用途：说明当前二值训练的实际数据流，区分冻结训练、联合微调与从零训练，记录已有证据和可比较的研究方案。

日期：2026-10-20。本轮只检查实现与现有产物，不启动新训练，也不修改训练源码、配置或权重。

## 当前模型怎样训练

当前采用两阶段训练：先训练浮点描述子，再加载其 checkpoint、冻结主干，仅训练二值 hash head。

```text
阶段 1：patch → 浮点 backbone → 单位描述子 f → 浮点匹配损失
阶段 2：patch → 冻结 backbone → 归一化前特征 q256
       → ResidualHashHead → logits z512 → STE 硬二值码 → 二值匹配损失
```

冻结同时使用 `requires_grad=False`、`eval()` 和 `no_grad()`，分别禁止参数更新、固定训练态行为和避免记录主干梯度。hash head 输入是 q，不是已 L2 归一化的 f；默认 512 bit，隐藏层 1024，使用 AdamW 只更新 head。部署时只有一套 backbone + hash head，不额外运行第二个 teacher 网络。

已有 m0 / m2 二值产物均为 `backbone_trainable=false`、512 bit。m0 的浮点来源为 epoch 4，二值 best 为 epoch 145，温度约 0.108；m2 的浮点来源为 epoch 30，二值 best 为 epoch 3，温度约 0.955。`best` 不一定是最后一轮，也不一定已经到低温阶段。

## 硬码如何反向传播

```python
a = tanh(z / T)
hard = where(z >= 0, +1, -1)
b = a + (hard - a).detach()
```

`detach()` 使括号内的差值不参与反向传播：前向的 b 已经是 ±1 硬码；反向在 STE 处借用 tanh 的梯度 `(1 - tanh(z/T)**2) / T`。这不是训练结束才第一次取 sign。

T 随训练 step 指数退火 `1.0 → 0.1`。对于同一组固定 logits，T 不改变 `z >= 0` 得到的硬码；它改变梯度与软表示的正则项，从而影响后续学到的权重。较低温度不自动意味着更高精度。

## 当前损失与负样本

- 主 metric 权重 1.0；teacher 相似关系保持 0.5；正样本连续码一致性 0.1；量化约束 0.1；bit 均衡 0.02；bit 去相关 0.02。
- metric 对单位化 STE 硬码计算，使用 top-k=3，最近 top-1 权重 0.6。允许合法同指负样本，同时屏蔽相同 point_group；同指、同一坐标系的点须满足 `max(|dx|, |dy|) >= 16 px`。
- 对单位化 ±1 码，`L2 = 2 * sqrt(归一化 Hamming 距离)`，因此二者排序一致；训练 margin 的数值不能直接当 Hamming 阈值。

## 三条训练路线

**A：浮点预训练 → 冻结主干训练 head。** 当前实现与已有二值产物采用这一条。优点是保留已学特征、优化范围小；限制是主干无法主动适应量化造成的信息损失。

**B：浮点预训练 → 主干与 head 联合训练。** 当前有 `backbone_trainable=true` 开关，但从浮点 checkpoint 启动时 head 仍为随机初始化。它不等于已经支持“浮点 → 冻结训练头 → 联合微调”的自动三阶段流程；从 frozen binary checkpoint resume 时直接改开关会触发元数据不匹配。

**C：全部随机初始化 → 从零联合 binary 训练。** 这是另一项实验，不应和端到端学习混为一谈。当前 CLI 强制提供 float/L2 checkpoint，因此尚不支持；需要独立入口，并明确 teacher 关系项是否保留及如何设计，不能只删除 checkpoint 检查。

## 联合微调时的两个实现边界

当前 teacher_f 和 q 都来自同一个 backbone。主干解冻后，它们会随权重更新；loss 内的 `teacher.detach()` 只阻止当次梯度流入目标，不会创建独立固定 teacher。若要保护原浮点教师关系，需要额外设计冻结副本或特征缓存。

优化器当前使用同一个学习率，没有自动给主干设置更小学习率。若后续实施 A → 联合微调，需要设计新阶段的模型权重加载、重新构造 optimizer 与学习率，而不是直接修改 frozen checkpoint 的 resume 配置。本轮不实现这些变化。

## 从零训练会不会更好

目前没有本项目 A / B / C 的严格对照，不能判断从零训练更准。研究上可优先评估“保留浮点初始化，再让主干温和适应二值目标”；这只是待验证建议，不是已选定方案或已有收益。

[HashNet](https://arxiv.org/abs/1702.00758)讨论平滑近似 sign、逐步解决离散优化的动机，不证明从零训练优于预训练。[DLBD（CVPR 2023）](https://openaccess.thecvf.com/content/CVPR2023/papers/Xiao_DLBD_A_Self-Supervised_Direct-Learned_Binary_Descriptor_CVPR_2023_paper.pdf)第 4.2 节使用 ImageNet 预训练参数，说明 direct-learned / end-to-end 并不等于随机初始化；这些论文也不是本项目指纹数据上的结论。

建议先固定同一个 Mobile 主干、256 bit、按 finger 不变的划分，对照 A / B / C，并加入 Hadamard256 基线。验证集分别调阈值后，在固定 FAR 下比较测试 FRR，运行多个随机种子并复核部署预算；若优先研究 A → 联合微调，应明确其初始化来自训练好的 A。

训练顺序在最终结构和码长相同时不会改变参数量、MACs 或 packed 大小。Mobile + Hadamard256 的本轮预算达标不能转授给尚无认证的 Mobile learned256 / 512。后者仍需满足[描述子生成 p95 <70 ms 与完整 1:1 / 40 模板 ΔRSS <30 MB](模型性能约束.md)，并单独验证精度。
