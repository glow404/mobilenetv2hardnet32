# 模型性能约束

用途：保存本项目已经确认的部署性能要求与验收口径，作为后续模型、二值化方式和推理实现的筛选依据。

确认日期：2026-10-20。

## 硬性要求

后续方案必须同时满足以下要求，不能只凭参数量、MACs、权重文件大小或某一段推理耗时判定达标。

- 目标机器：本机 AMD Ryzen 9 5900HX，8 核 16 线程；Windows；Python 3.13.9；CPU FP32 ONNX Runtime 推理环境。
- 工作负载：一张灰度指纹图像，约 400 个有效关键点，最终生成约 400 个打包后的二值描述子。
- 时间：充分预热后，从灰度图像到 packed 二值描述子就绪的延迟 **p95 < 70 ms**，不含之后的匹配与身份判定。
- 内存：从请求开始到最终身份判定结束的完整 1:1 识别请求，其峰值 RSS 相对完整识别路径预热后空闲基线的增量 **严格小于 30,000,000 bytes**，即十进制 30 MB，约 28.61 MiB。
- 应用场景：**1:1 指定身份验证，每个身份使用 40 张注册模板**；不能用 1:N 全库检索的工作负载代替这一场景。

## 时间测量边界

计时覆盖以下完整路径：

```text
灰度图像 → 关键点检测 → patch 裁剪 → 标准化 → CNN 描述子前向
         → 二值化 → bit 打包 → 本次请求的 packed 二值描述子就绪
```

上述步骤都必须计入同一个请求的特征提取耗时；其后的模板匹配、候选筛选、RANSAC、纹理验证和最终判定不计入这项 70 ms 指标，但都计入下述内存峰值的测量范围。单独测量 CNN 或单独测量二值化，只能用于定位瓶颈，不能作为该时间指标的验收值。

本轮测量以**已经位于内存中的灰度图像**为起点，因此不包含图像磁盘读取、文件解码与转灰度。磁盘读取是否需要纳入正式产品边界尚未明确；这是本轮采用的测量边界，不代表用户已逐项确认这些排除项。

预热必须运行上述完整路径，并覆盖实际使用的约 400 个 patch 的形状与分批方式。记录实际检测、保留和输出的关键点 / 描述子数量，避免通过显著减少工作量获得达标结果。验收使用预热后的整段请求延迟分布，报告测量次数、p50、p95 和 p95 的计算方法，不能以平均值代替 p95。

## 内存测量边界

RSS 表示进程当前驻留的物理内存；Windows 测量时应明确采用的工作集 / RSS 采集接口。内存测量覆盖灰度图像请求开始、关键点检测、patch 裁剪、标准化、CNN、二值化打包，随后继续覆盖与指定身份 40 张注册模板的匹配、候选筛选、RANSAC、纹理验证，直到最终身份判定结束。**时间与内存指标的终点不同：70 ms 计时在 packed 描述子就绪时停止，内存采样在完整身份判定结束时停止。** 验收计算为：

```text
baseline_RSS = 包含 40 模板匹配与最终身份判定的完整识别路径充分预热、回到空闲状态后的进程 RSS
peak_RSS     = 单次识别请求开始至最终身份判定结束期间的最高 RSS
ΔRSS         = peak_RSS - baseline_RSS
验收要求     = ΔRSS < 30,000,000 bytes
```

模型、ONNX Runtime 运行时和注册模板已经常驻产生的内存计入 `baseline_RSS`，不重复计入本次请求增量。请求期间新分配或首次驻留的临时数组、patch、激活、中间描述子、打包结果、匹配距离与候选数组、RANSAC 和纹理验证中间结果等，应由全请求峰值采样反映。

必须同时报告以下数值，防止较小的增量掩盖较大的常驻空间：

- 完整路径预热后的绝对 `baseline_RSS`。
- 请求的绝对 `peak_RSS` 和计算出的 `ΔRSS`；内存硬限值按峰值增量判断，不按 p95 内存判断。
- 加载模型 / 运行时 / 模板后的空闲 RSS，以及首次运行完整路径产生的扩容峰值与扩容量。
- 预热次数、最大预热输入形状、内存池 / 缓存行为、RSS 采样方式和采样间隔。

预热形成的常驻内存和首次扩容必须单独呈现，不能隐藏，也不能与单请求增量混为一项。权重文件大小、模型参数字节数和描述子净大小均不能替代实际 `ΔRSS` 测量。

## 对照与验收记录

方案筛选应在上述 AMD 本机环境、相同图像与约 400 个有效 patch 的负载下进行，记录模型 / checkpoint、二值码长、实际执行后端、ONNX Runtime / OpenCV 版本、线程数、batch 与分块配置。若某些算子仍由 PyTorch 等其他后端执行，应明确记录实际混合执行路径。

旧的 Intel i7 基准或其他设备数据只能作为参考，不能认证此 AMD 机器满足约束；理论 MACs、参数量和描述子压缩率也不能代替本机完整路径实测。

每次验收记录应列出上述延迟和内存证据，再给出该配置是否**同时满足**时间与内存要求的结论。本文件先固定要求和测量口径；具体模型的通过 / 失败结论由对应本机实测记录给出。
