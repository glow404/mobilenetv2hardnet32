## 优化器决策

默认使用带 momentum 的 SGD，并开启 Nesterov；AdamW 保留为可配置对照。

| 方法 | 核心思想 |
| --- | --- |
| SGD | 使用当前梯度更新参数 |
| Momentum | 累积历史更新方向 |
| Nesterov | 在预估位置计算修正梯度 |
| AdamW | 自适应学习率与解耦 weight decay |

HardNet 的 hardest-in-batch 度量学习优先以 SGD 的最终泛化能力为基线，不能仅根据短程收敛速度切换优化器。

## 学习率调度

使用带预热的余弦退火。

## 实施状态

1. 固定 in-batch 验证计划
- `R0/R1/R2` 不合并，完整 `finger_id` 作为物理手指身份。
- `validation.finger_count: auto` 使用 `min(验证集可用手指数, batch_size)`，实际值写入 resolved config 和 checkpoint。
- 由 `batch_count` 控制每轮固定验证 batch 数量，对应训练侧的 `steps_per_epoch`。
- 每根手指的 `image_pair_id` 固定洗牌后依次使用；全部用完时重新洗牌循环。
- 同一验证 batch 内每根手指仍只使用一个 `image_pair_id`，样本分配与训练 sampler 一致。
- 不再为每个 anchor 预分配固定数量负样本；验证直接复用训练的 `point_group`、空间过滤、双向候选和 top-k 规则。
- 合法候选不足 k 时只使用现有候选；单个 anchor 无候选时跳过并计数，整个计划无有效 anchor 时才报错。

2. 验证指标
- 主选模与 early stopping 字段为 `val_fpr_at_tpr95`。
- ROC、ranking 和距离分位数只汇总固定 batch 内实际被 top-k 选中的合法负样本。
- 同指纹和跨指纹分别输出 `val_same_finger_*`、`val_cross_finger_*` 指标。
- `val_valid_anchor_count` 与 `val_skipped_anchor_count` 明确记录有效/跳过 anchor 数量。
- 这些是 patch 层固定 in-batch 指标，不替代完整指纹匹配层 FAR/FRR 评估。

3. 优化器和参数分组
- 默认使用 `SGD + momentum + Nesterov`，可通过 `optimizer.name: adamw` 切换到 AdamW。
- Conv/Linear 权重应用 `weight_decay`；BatchNorm 参数和所有 bias 使用 `weight_decay=0`。
- 更换优化器或启用新验证协议时必须使用新输出目录从头训练，不恢复旧 optimizer state。

```yaml
optimizer:
  name: sgd
  lr: 0.1
  momentum: 0.9
  nesterov: true
  weight_decay: 0.0001

validation:
  protocol: fixed_in_batch_v1
  seed: 10042
  finger_count: auto
  batch_count: 256
  batch_size: 24
```

切换 AdamW 时应同时显式设置实验学习率，例如 `name: adamw`、`lr: 0.001`；程序不会根据优化器名称静默改写学习率。

4. 实验记录与兼容边界
- 命令行覆盖会先回写实际配置，再保存到 `resolved_config.json` 和 checkpoint，修复目录名与实际 batch size 可能不一致的问题。
- 新实验默认输出到 `outputs/models/hardnet_train_strong_v2_256_fixed_in_batch_v1`，避免混入旧 fixed-pair 指标 CSV。
- 旧模型 checkpoint 的推理加载兼容保留；旧指标 CSV 不再兼容续写。

5. 训练与验证报错风险
- 启动前拒绝非法 batch、手指数越界、旧验证字段/协议、CSV 无可用数据、跨指策略不足两根手指、checkpoint 契约不一致和已有指标被意外覆盖。
- `batch_count` 大于 image pair 数量不会报错，image pair 会按固定 seed 循环；但耗时、固定计划和 CPU 指标缓存按 `batch_count × batch_size` 近似线性增长。
- 每批验证指标会立即转存 CPU，因此增加 `batch_count` 不直接抬高单步 GPU 峰值；超过十万个正样本槽位会警告，超过一千万会提前拒绝。
- 训练 CUDA OOM 主要由训练 `batch_size` 和模型决定；HardNet 距离矩阵按 `batch_size²` 增长。
- patch 路径失效/图片损坏、Windows DataLoader worker、NaN/Inf、磁盘空间或写权限仍属于运行时风险。
- 无合法负样本的单个 anchor 会跳过并计数；只有整个验证计划都无有效 anchor 才失败。

6. margin 设置为少部分 Triplet 失效，可能效果更好。
